## 2. Top 5 Cycle-7 Zero-Dep (`ROOT_DEPS=6`) Pioneering Breakthroughs

All 5 build cleanly on Culkibo's existing `ROOT_DEPS=6` (`express`, `ws`, `chokidar`, `commander`, `cors`, `dotenv`), 0 shell calls, and `<= 60 MB` idle RSS:

### 1. Zero-Dep Interactive Container Web Terminal (`server/services/containerTerminalService.js`)
- **Inspiration:** [`getarcaneapp/arcane`](https://github.com/getarcaneapp/arcane) & [`louislam/dockge`](https://github.com/louislam/dockge) live browser shell UX — without `node-pty` native compilation or heavy bundles.
- **Design:** Bridge existing `ws` (`/ws/terminal`, gated by single-use WS ticket + `runtime:exec` RBAC + project ACL) directly to Docker Engine API over Unix socket / named pipe (`POST /containers/:id/exec` with `Tty:true, AttachStdin/Stdout:true`, then `POST /exec/:id/start` via Node `http.request` `Connection: Upgrade, Upgrade: tcp` raw stream hijack, plus `POST /exec/:id/resize` on JSON `{type:'resize',cols,rows}`). Enforce 15-min idle timeout, `<= 4` concurrent sessions/user, strict command allowlist (`['/bin/sh']` / `['/bin/bash']`), and audit-log session open/close metadata. Pair with a tiny zero-dep ANSI/VT100 React terminal pane in `ProjectDetail.tsx`.

### 2. Zero-Config Fleet WireGuard Mesh (`server/services/fleetMeshService.js`)
- **Inspiration:** [`juanfont/headscale`](https://github.com/juanfont/headscale) & [`netbirdio/netbird`](https://github.com/netbirdio/netbird) private VPS mesh — eliminating Swarm overlay fragility (`dokploy#4265`) and public DB exposure (`kamal#1856`).
- **Design:** Generate peer Curve25519 keys with native Node `crypto.generateKeyPairSync('x25519')` (stored AES-256-GCM encrypted in vault), assign deterministic private mesh IPs (`10.88.0.1..254/24`), render auditable `wg0.conf` + safe `ufw`/nftables check plan, and distribute peer tables atomically across fleet hosts via existing zero-shell `serverFleetManager.js` SSH tunnels. Includes dry-run topology diff and per-peer key rotation (`POST /api/fleet/mesh/rotate`).

### 3. Cron Visual Timeline + Dead-Man's-Switch Heartbeats (`server/services/cronManager.js` + `uptimeMonitor.js`)
- **Inspiration:** [`healthchecks/healthchecks`](https://github.com/healthchecks/healthchecks) push-based dead-man's-switch monitors (catches *silent* failures when a cron never fires!).
- **Design:**
  - **Heartbeat Check-Ins:** Add per-cron & standalone external heartbeat monitors (`POST/GET /api/heartbeat/:token[/{start|fail}]`, constant-time token verify, configurable `periodSec` + `graceSec` + duration tracking). Missing a ping past `lastPing + periodSec + graceSec` fires a deduplicated `alertEngine.js` incident (`heartbeat_missed`) and auto-resolves on next check-in.
  - **24h Cron Collision Timeline (`GET /api/crons/timeline`):** Project next 24h fire windows across all project crons + DB backup schedules using `cronParser.js`, flagging overlapping heavy-IO windows (`collisionWarnings[]`) so users stagger builds/backups visually and avoid VPS OOM spikes.

### 4. Caddy Native Edge Bot-Shield & Zero-Plugin PoW Challenge (`server/services/caddyManager.js` + `edgeShieldService.js`)
- **Inspiration:** [`TecharoHQ/anubis`](https://github.com/TecharoHQ/anubis) cryptographic AI-scraper Proof-of-Work + [`corazawaf/coraza-caddy`](https://github.com/corazawaf/coraza-caddy) OWASP edge defense — zero extra Caddy plugins required!
- **Design:**
  - **Native Caddy JSON Bot/Exploit Matchers:** Opt-in per-domain `edgeShield` policy compiling pure Caddy v2.11 matchers blocking scanner probes (`/.env`, `/.git`, `/wp-config.php`, traversal `../`, SQLi/XSS query patterns) and configurable abusive AI scraper UAs with `403` + zero upstream load.
  - **Zero-Dep Hashcash PoW Gate (`edgeShieldService.js`):** When `powChallenge: true`, suspicious clients lacking a valid HMAC-SHA256 clearance cookie (`ckb_shield`, IP+UA bound, 24h TTL) hit Culkibo's lightweight `/api/edge-shield/challenge` page running a sub-second WebCrypto SHA-256 puzzle before Caddy proxies them cleanly — sovereign Anubis-class scraper defense built right in!

### 5. Deterministic Build-Log Classifier & Auto-Dockerfile/Compose Healer (`server/services/buildHealerService.js`)
- **Design:** Pure-JS stderr/log diagnostic engine (0 external LLM calls needed, exposed both in UI build failure banners and as MCP tool `culkibo_heal_build_failure` with `dryRun` + `ckr_` confirmToken) classifying 20+ real build/runtime failure patterns:
  - Node heap OOM (`Reached heap limit` → suggest `NODE_OPTIONS=--max-old-space-size=...` + SmartPack cgroup balance), missing native build toolchain (`node-gyp`/`python3`/`make`), `npm ci` lockfile drift, Next.js missing `output: 'standalone'`, port mismatch (`EADDRINUSE` / container bound `127.0.0.1` instead of `0.0.0.0`), Docker log-opt mismatch (`kamal#1709`), missing Compose `mem_limit`, and Postgres `pg_wal` / `max_connections` saturation. Returns `{ code, rootCause, confidence, patchPreview, autoFixAction }`.

## 3. Exact Competitor PR Regressions to Add in Cycle #7 (`tests/competitor-prs.test.js`)
